# Mini App на существующем сервере Docker + Nginx

Этот вариант использует отдельное имя хоста и отдельный конфиг Nginx.
Существующие виртуальные хосты и соседние Compose-проекты не меняются.
API остаётся на `127.0.0.1:8000`; наружу проксируются только панель и её API.

## Предварительно

- Проект располагается в `/opt/finance`, Compose-проект называется `finance`.
- Postgres и ранее настроенный Xray уже работают.
- Отдельный сертификат для имени хоста получен через Certbot webroot,
  `--cert-name finance-miniapp`, webroot `/var/www/finance-acme`.
- Создан отдельный HTTP-конфиг
  `/etc/nginx/sites-available/zz-finance-miniapp.conf` с первой строкой
  `# Budget Bot Mini App` и одноимённая ссылка в `sites-enabled`.

Можно использовать собственный домен. Для проверочного запуска без него
подойдёт адрес DNS-сервиса с IP, например `finance.176-12-71-51.sslip.io`.
Адрес зависит от доступности DNS-сервиса и сохраняется, пока не меняется IP.

## Установка

Основной способ доставки кода — Git. Для уже настроенного сервера с чистым
рабочим деревом:

```bash
cd /opt/finance
git pull --ff-only origin main
bash deploy/enable-miniapp.sh finance.176-12-71-51.sslip.io
```

Если первая установка была выполнена архивом поверх Git checkout, сначала
закоммить и отправь те же изменения из локального проекта в `origin/main`.
На сервере проверь `git status --short`, сохрани установленный код в stash
и получи коммит:

```bash
cd /opt/finance
git stash push --include-untracked -m "Before Git sync: deployed Mini App"
git pull --ff-only origin main
git status --short
```

Stash остаётся резервной копией; не применяй его поверх полученного коммита,
который уже содержит изменения Mini App. Игнорируемые `.env` и `data/` в stash
не переносятся. Конфиг Nginx и сертификат находятся за пределами репозитория.
Если полученный коммит совпадает с уже запущенным кодом, перезапуск не нужен.

### Альтернативная доставка архивом

Перед распаковкой обновлённого кода сохрани текущий исходный код:

```bash
cd /opt/finance
install -d -m 700 data/backups
git archive --format=tar.gz HEAD > "data/backups/source-before-miniapp-$(date -u +%Y%m%d-%H%M%S).tar.gz"
```

Распакуй подготовленный архив проекта в `/opt/finance`. Архив не должен содержать
`.env`, `.git`, runtime-данные и резервные копии. Затем:

```bash
cd /opt/finance
bash deploy/enable-miniapp.sh finance.176-12-71-51.sslip.io
```

Скрипт:

1. Проверяет сертификат и работающий Postgres.
2. Сохраняет `.env` и резервную копию БД в закрытом каталоге `data/backups/`.
3. Задаёт HTTPS URL, собирает образы и останавливает только бота `finance`.
4. Применяет миграции и проверяет неизменность существующих записей.
5. Запускает API, проверяет локальный health endpoint.
6. Заменяет только отмеченный конфиг финансов, проверяет Nginx и перезагружает его.
7. Дожидается готовности HTTPS после reload с проверкой сертификата,
   проверяет отказ API без входа, затем запускает бота.

В конце отправь `/web` в личном чате с ботом и нажми «Открыть приложение».
Сертификат обновляется Certbot через прежний HTTP webroot.

При ошибке остановись и сохрани вывод. Если проверка Nginx/HTTPS не прошла,
скрипт восстановит `.env` и собственный прежний конфиг. Бот может остаться остановленным;
скрипт не откатывает БД автоматически и не удаляет пользовательские данные.
Резервный каталог выводится в сообщении ошибки.
