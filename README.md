# Budget Bot

Локальный MVP для автозаполнения бюджета из скриншотов банковских операций.

## Что делает

- принимает скриншоты из Telegram или через HTTP upload;
- принимает в Telegram текстовые PDF «Справка о движении средств» Т-Банка;
- отправляет картинку в vision LLM;
- получает строгий JSON операций;
- валидирует категории по справочнику пользователя в Postgres;
- автозаписывает уверенные операции в Postgres;
- строит отчеты из Postgres;
- формирует Excel-файл по запросу в прежнем формате;
- переводы и спорные операции оставляет на решение в Telegram;
- хранит историю, дубли и ручные состояния в Postgres.

PDF-выписки разбираются локально, без отправки документа в LLM: используется
дата операции и сумма в валюте карты. Перед записью суммы сверяются с итогами
выписки. Категории определяются по локальным и выученным правилам; неизвестные
категории, переводы и доходы требуют решения в Telegram. Повторные файлы и
операции проходят существующую проверку дублей. Поддерживаются исходные
текстовые справки до 50 страниц в пределах `MAX_UPLOAD_BYTES` (по умолчанию
10 МБ); сканы, PDF с паролем и форматы других банков пока не поддерживаются.

## Быстрый старт

```bash
cp .env.example .env
```

Заполни `.env`:

```bash
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ALLOWED_USER_IDS=123456789
LLM_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4o-mini
DATABASE_URL=postgresql://budget_bot:budget_bot@127.0.0.1:5433/budget_bot
BUDGET_EXPORT_DIR=./data/exports
BUDGET_API_TOKEN=local-secret-for-http-upload
REMINDER_ENABLED=true
REMINDER_DEFAULT_TIME=21:00
```

Запустить весь runtime в Docker:

```bash
docker compose up --build bot
```

Эта команда поднимет Postgres и Telegram-бота. Python тоже запускается внутри
контейнера. Экспорты и сохраненные скриншоты будут лежать в локальной папке
`data/`, потому что она примонтирована в контейнер.

`TELEGRAM_ALLOWED_USER_IDS` обязателен для Telegram-бота. Для локального теста без
ограничения доступа можно явно поставить `TELEGRAM_ALLOW_ALL=true`, но для реального
использования лучше оставить allowlist.

По умолчанию Docker Compose не публикует Postgres наружу. Контейнеры приложения
подключаются к базе по внутреннему адресу `postgres:5432`, поэтому на сервере порт
БД не открыт в интернет.

Если Telegram или OpenAI не открываются из текущей сети, `requests` использует
стандартные переменные прокси:

```bash
HTTPS_PROXY=http://127.0.0.1:7890
HTTP_PROXY=http://127.0.0.1:7890
```

Надежнее задать прокси только для Telegram:

```bash
TELEGRAM_PROXY_URL=http://127.0.0.1:7890
# или для SOCKS:
TELEGRAM_PROXY_URL=socks5h://127.0.0.1:1080
```

OpenAI использует `OPENAI_PROXY_URL`, а если он не задан — автоматически берет
`TELEGRAM_PROXY_URL`. Если нужен отдельный прокси для OpenAI:

```bash
OPENAI_PROXY_URL=http://127.0.0.1:7890
PYTHONPATH=src python -m budget_bot.cli openai-check
```

Если в системе уже задан нерабочий прокси и бот молчит/пишет `ProxyError`,
отключи env proxy для приложения:

```bash
USE_ENV_PROXY=false
```

Для VLESS + Reality можно включить отдельный сервис Xray. В `.env` добавь:

```dotenv
COMPOSE_FILE=docker-compose.yml:docker-compose.vless.yml
XRAY_CONFIG_JSON='{"log":{"loglevel":"warning"},"inbounds":[{"listen":"0.0.0.0","port":8080,"protocol":"http","settings":{}}],"outbounds":[{"protocol":"vless","settings":{"vnext":[{"address":"YOUR_SERVER","port":443,"users":[{"id":"YOUR_UUID","encryption":"none","flow":"xtls-rprx-vision"}]}]},"streamSettings":{"network":"tcp","security":"reality","realitySettings":{"serverName":"YOUR_SNI","fingerprint":"firefox","publicKey":"YOUR_PUBLIC_KEY","shortId":"YOUR_SHORT_ID"}}}]}'
```

Значения берутся из VLESS-ссылки: сервер и порт после `@`, UUID перед `@`,
`sni` → `serverName`, `fp` → `fingerprint`, `pbk` → `publicKey`,
`sid` → `shortId`. Пример рассчитан на TCP + Reality + Vision.
JSON должен оставаться одной строкой в одинарных кавычках; реальные данные
подключения храни только в `.env`.

Запуск остаётся прежним: `docker compose up --build bot`. Compose поднимет
Xray и задаст контейнерам приложения `TELEGRAM_PROXY_URL=http://xray:8080`.
HTTP-прокси доступен только внутри Docker, порт на компьютере не публикуется.
Если `OPENAI_PROXY_URL` пуст, OpenAI тоже использует этот туннель по существующему
правилу. Отдельно заданный `OPENAI_PROXY_URL` сохраняет приоритет.
Для запуска Python на компьютере нужен другой доступный ему адрес прокси:
имя `xray` разрешается только внутри Docker.

Чтобы отключить туннель, убери `COMPOSE_FILE` из `.env` и пересоздай бот:
`docker compose up -d --force-recreate bot`. Он снова возьмёт прокси из `.env`.
Уже запущенный Xray можно остановить до удаления `COMPOSE_FILE` командой
`docker compose stop xray`.

Для локального или проксированного Telegram Bot API можно переопределить:

```bash
TELEGRAM_API_BASE_URL=http://127.0.0.1:8081
TELEGRAM_FILE_BASE_URL=http://127.0.0.1:8081/file
```

`TELEGRAM_TIMEOUT_SECONDS` по умолчанию 60. Не ставь меньше 35: long polling
ждет Telegram до 30 секунд.
`REMINDER_DEFAULT_TIME` задает локальное время ежедневного Telegram-напоминания
в timezone из `DEFAULT_TIMEZONE`. Бот проверяет напоминания раз в час, поэтому
сообщение может прийти не ровно в указанную минуту.

Проверить конфиг и справочник:

```bash
docker compose run --rm bot python -m budget_bot.cli migrate
docker compose run --rm bot python -m budget_bot.cli check
```

Сформировать Excel из Postgres:

```bash
docker compose run --rm bot python -m budget_bot.cli export-excel --owner default
docker compose run --rm bot python -m budget_bot.cli export-excel --owner default --period 01.08-24.08
```

Запустить Telegram long polling:

```bash
docker compose run --rm bot python -m budget_bot.cli telegram-check
docker compose up --build bot
```

После запуска в терминале должно появиться `Telegram polling started for @...`.
В Telegram можно написать `/ping`: бот должен ответить `pong`, а в терминале
должна появиться строка `Telegram update ...`.
Команда `/reset` в Telegram показывает кнопку подтверждения для очистки расходов,
доходов, истории обработанных скринов и сохраненных копий скриншотов.
Кнопки внизу чата заменяют частые команды: `+ Расход`, `+ Доход`,
`Аналитика`, `Синхронизировать`, `Сброс`. Кнопка `Синхронизировать`
теперь запускает Excel export.
`Аналитика` открывает компактное меню с отчетами: месяц, сегодня, неделя,
категории и выбор дат.
В аналитике доступны отдельные экраны: расходы, сравнение категорий,
доходы и остаток, динамика за 6 месяцев, лимиты, прогноз и настройки.
Отчёты отправляются текстом; диаграмму можно получить отдельной кнопкой.
Текущий месяц сравнивается с теми же датами прошлого месяца, полный месяц —
с полным предыдущим; произвольный период — с предшествующим отрезком той же длины.

В `Настройки → Выбрать обязательные` можно отметить категорию целиком или
отдельную подкатегорию, например `Дом / Аренда`. Для отдельной операции:
`Расходы → Записи → нужная запись → Отметить обязательной`.
Переключатель `Все / без обязательных` применяется к расходам, сравнению,
диаграммам, динамике, прогнозу и лимитам. В отчёте видна исключённая сумма.
Доходы и остаток всегда учитывают все операции; экспорт Excel также содержит все записи.
Остаток — это доходы минус расходы за период, не баланс банковского счёта.

Общий месячный лимит: `/limit 60000`; по категории: `/limit Еда | 15000`.
Сумма `0` удаляет соответствующий лимит. В личном чате бот уведомляет при
достижении 80% и 100%, один раз за месяц для каждого порога и режима фильтра.
Недельная сводка включается в настройках в личном чате: по понедельникам после
09:00 в настроенном часовом поясе. При включении и после простоя отправляется только последняя
завершённая неделя. Настройки аналитики сохраняются при сбросе операций.
Прогноз — приблизительная линейная оценка по записанным тратам; будущие
фиксированные платежи и неполная история могут существенно изменить результат.

Для нескольких пользователей бот ведет отдельный бюджет по Telegram user id:
история, дубли, ручные решения, выученные категории и операции не
перемешиваются. При первом появлении пользователя бот создает дефолтный
справочник категорий в Postgres. Команда `/budget` показывает текущую БД.
`+ Расход` и `+ Доход` запускают ручное добавление без скрина: бот спросит дату,
сумму и категорию кнопками.
После записи бот удаляет промежуточные сообщения ручного ввода и оставляет в чате
только итоговое `Засчитано`.
Быстрый ввод одной строкой тоже работает:

```text
-36857 07.08 Дом / Аренда
+51700,70 07.08 Зарплата
```

Команда `/stats` показывает расходы за текущий месяц из Postgres, а
`/stats 01.08-24.08` или обычный текст `01.08-24.08` — за выбранный период.
Команда `/export` и кнопка Excel export выгружают все записи пользователя за всё время из Postgres. `/export 01.08-24.08` ограничивает выгрузку указанным периодом. CLI `export-excel` без `--period` также выгружает все записи выбранного владельца.
`/sync` оставлен как deprecated-подсказка и предлагает использовать `/export`.
Команда `/reminders` показывает время ежедневного напоминания.

Запустить FastAPI:

```bash
docker compose --profile api up --build api
```

HTTP upload защищен bearer-токеном:

```bash
curl -H "Authorization: Bearer $BUDGET_API_TOKEN" \
  -F "file=@screenshot.jpg" \
  http://127.0.0.1:8000/parse-image
```

Если бот пишет `OpenAI rejected the API key with 401 Unauthorized`, проверь
`OPENAI_API_KEY` в `.env`: ключ должен быть актуальным, без лишних пробелов и с
доступом к выбранной модели.

## Важное по Excel

Excel больше не является хранилищем. Он формируется по запросу из Postgres и
содержит прежние листы:

- `Учет расходов`, таблица `УТ_Данные`;
- `Учет доходов`, таблица `УчетДоходов`;
- `Справочники`.

## Поведение

- Валидные расходы записываются сразу, если тип, сумма и категория проходят backend-проверку.
- Доходы со скрина не записываются автоматически: бот предлагает `Считать доход` или `Пропустить`.
- Кэшбэк, бонусы и бонусные бейджи около операции игнорируются: они не пишутся и не отправляются на ручное решение.
- `transfer`, дубли, неизвестные категории и неполные данные не пишутся автоматически.
- Если банк показывает категорию под названием операции, модель использует ее как сильную подсказку и сопоставляет с разрешенным справочником.
- Вместо числовой уверенности модель возвращает `needs_review`: такие операции уходят на ручное решение и не пишутся сразу.
- OpenAI JSON Schema ограничивает категории/подкатегории значениями из Postgres-справочника; пара всё равно повторно проверяется в backend.
- Для переводов бот предлагает `Считать` или `Пропустить`; если считать, дальше показывает кнопки категорий и подкатегорий.
- После нажатия Telegram-кнопки бот удаляет сообщение с этой клавиатурой, чтобы кнопки не копились в чате.
- Текстовый ответ `Категория / Подкатегория` тоже остается как запасной вариант.
- Ручное добавление без скрина пишет операцию сразу в Postgres после выбора суммы и категории.
- Ручной выбор категории запоминается по названию операции; следующая такая же операция будет записана автоматически.
- Несколько скринов, отправленных одним Telegram-альбомом, обрабатываются одним LLM-запросом как одна пачка одного дня.
- После обработки бот присылает сводку записанных операций по датам с названием, суммой и категорией.
- Главное меню Telegram содержит компактные постоянные кнопки внизу чата: ручное добавление, аналитика, Excel export и сброс.
- Ежедневное напоминание отправляется один раз в день в заданное локальное время, если включено.
- Если дата операции на скриншоте не видна, бот спрашивает ее в Telegram. Ответ: `22.08`.
- Если на одном скрине есть одинаковые операции с тем же названием, суммой, датой и типом, бот спрашивает, сколько из них записать.
- `/reset` очищает Postgres-операции, историю обработанных скринов и `data/images` после подтверждения кнопкой.

## Модель OpenAI

Рекомендуемая модель для MVP: `gpt-4o-mini`.

Почему она:

- принимает скриншоты как image input;
- возвращает JSON через Structured Outputs;
- достаточно дешевая для частых скринов;
- быстрая для Telegram-flow.

Если на реальных скринах будет путать даты, строки или категории, попробуй заменить:

```bash
OPENAI_MODEL=gpt-4.1-mini
```
