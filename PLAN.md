# План: Telegram-бот для автозаполнения бюджета из скриншотов банков

## Summary

Сделать локальный MVP на Python + FastAPI: ты отправляешь скрин истории операций из Т-Банка/Сбера/Альфы/Тинькофф в Telegram, бот распознает операции через vision LLM, валидирует JSON, автозаписывает уверенные расходы/доходы в текущий Excel, а спорные операции спрашивает в Telegram.

Excel остается основным отчетом с графиками и фильтрами. SQLite добавляется как техническая база для истории импорта, дублей, статусов и ожидания твоих ответов.

По стоимости LLM: заложить адаптер провайдера и начать с дешевого vision-кандидата, скорее всего Gemini Flash/аналог, затем проверить качество на 20-30 твоих скринах. По официальным ценам Gemini 2.5 Flash имеет paid input для text/image/video $0.90 за 1M токенов и free tier, Claude Haiku vision оценивается примерно от $1.30 за 1000 изображений 1000x1000, OpenAI pricing тоже держать как fallback для качества. Источники: [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Claude vision pricing](https://platform.claude.com/docs/en/build-with-claude/vision), [OpenAI pricing](https://developers.openai.com/api/docs/pricing).

## Key Changes

- Создать локальное FastAPI-приложение с Telegram-ботом:
  - принимает фото/скриншоты;
  - сохраняет файл во временное хранилище;
  - отправляет изображение в LLM vision;
  - получает строгий JSON;
  - валидирует и записывает результат.
- Использовать SQLite:
  - `source_images`: telegram file id, hash изображения, банк, статус;
  - `operations`: распознанные операции, hash операции, статус `auto_written | pending | ignored | failed`;
  - `pending_actions`: операции, по которым бот ждет решения пользователя.
- Использовать текущий Excel:
  - расходы писать в таблицу `УТ_Данные` на листе `Учет расходов`;
  - доходы писать в таблицу `УчетДоходов` на листе `Учет доходов`;
  - в `Месяц` и `Год` копировать формулы с предыдущей строки;
  - в `Подробное описание` писать коротко или пусто;
  - в `Комментарий` писать источник, например `auto: tbank / Бургер Кинг`.
- Обновить справочник категорий:
  - в `Рестораны` заменить или добавить подкатегорию `Фастфуд`;
  - правило: Burger King/KFC/Вкусно и точка/банковская категория “Фастфуд” -> `Рестораны / Фастфуд`.

## Interfaces

LLM должен возвращать только JSON такого вида:

```json
{
  "bank": "tbank",
  "period": {
    "month": 8,
    "year": 2026,
    "screenshot_date": "2026-08-22"
  },
  "operations": [
    {
      "date": "2026-08-21",
      "name": "Бургер Кинг",
      "amount": -709.96,
      "type": "expense",
      "category": "Рестораны",
      "subcategory": "Фастфуд",
      "confidence": 0.94
    }
  ]
}
```

Правила записи:

- `type=expense`, `amount < 0`: писать в `Учет расходов`, сумма в Excel положительная.
- `type=income`, `amount > 0`: писать в `Учет доходов`.
- `type=transfer`: не писать автоматически.
- `confidence >= 0.90` и категория валидна: автозапись.
- `confidence < 0.90`, перевод, неизвестная категория или возможный дубль: Telegram-уточнение.

Telegram flow для переводов:

- Бот показывает: `Альберт X., -2000 ₽`.
- Кнопки: `Считать` / `Пропустить`.
- Если `Считать`, бот показывает кнопки категорий, затем кнопки подкатегорий.
- После выбора валидирует по `Справочники` и записывает как расход.
- Текстовый ответ `Категория / Подкатегория` остается запасным вариантом.

## Validation And Edge Cases

- Проверять, что `category` существует в `Справочники`, а `subcategory` входит в эту категорию.
- Не разрешать LLM создавать новые категории без ручного подтверждения.
- Дедупликация по hash: `bank + date + amount + name + type`.
- Если один скрин отправлен повторно, бот отвечает, что операции уже обработаны.
- Если на скрине даты вида `Вчера`, вычислять дату от даты отправки скрина.
- Если скрин показывает месяц без года, брать год из даты отправки.
- Переводы между людьми, переводы между своими счетами, кэшбэк и возвраты не писать молча.
- Кэшбэк на первом этапе отправлять на уточнение, пока не решим финальную логику дохода.

## Test Plan

- Проверить на твоем текущем скрине Т-Банка:
  - метро -> `Транспорт / Метро`;
  - Пятерочка -> `Продукты / Пятерочка`;
  - Бургер Кинг -> `Рестораны / Фастфуд`;
  - переводы -> pending в Telegram.
- Проверить дубли:
  - отправить один и тот же скрин дважды;
  - убедиться, что второй раз строки не добавляются.
- Проверить Excel:
  - новые строки появились в правильных таблицах;
  - `Месяц` и `Год` формулами посчитались;
  - дашборд/сводные видят новые данные после обновления в Excel.
- Проверить ошибки:
  - нечеткий скрин;
  - скрин без операций;
  - неизвестная категория;
  - операция с плюсом;
  - перевод с ручным выбором категории.

## Assumptions

- MVP запускается локально на твоем Mac.
- Excel-файл остается основным отчетом; SQLite используется только для технической надежности.
- Telegram-бот работает через long polling, чтобы не нужен был публичный HTTPS на локальной машине.
- LLM-провайдер выбирается через конфиг: сначала дешевый vision-кандидат, затем fallback на более качественный, если на банковских скринах будет много ошибок.
- На первом этапе поддерживаем скриншоты истории операций, а не PDF-выписки и не прямые банковские API.
